# Validation du prototype 0.1.0

Date : 15 juillet 2026.

## Verdict

Le prototype est utilisable localement pour son périmètre déclaré : délibération
visible, gel d'une spécification versionnée, débat d'architecture, routage de
trois fournisseurs, contrôle humain et campagne comparative hors ligne.

Ce verdict valide le logiciel, pas l'hypothèse scientifique de supériorité du
débat multi-agents.

## Vérifications automatisées

Commande de release :

```bash
npm run check
```

Elle couvre :

- typage TypeScript strict ;
- tests de la machine à états et des barrières humaines ;
- intégrité des identifiants de messages, sources et agents ;
- contrats OpenAI, Anthropic et Google avec clients simulés sans réseau ;
- routage réel par rôle derrière `AgentRuntimeAdapter` ;
- budgets, annulation, coût incertain et reprise ;
- exclusion de deux exécutions concurrentes et récupération d'un verrou
  orphelin ;
- atomicité message/coût et validation/artefact ;
- quatre conditions expérimentales et anonymisation ;
- reprise d'une campagne sans nouvel appel et analyse de classements aveugles ;
- compilation du binaire CLI ;
- cycle complet hors ligne jusqu'à `COMPLETED` ;
- campagne simulée avec les deux régimes de ressources ;
- génération de livrables Markdown aveugles ;
- création, installation propre et exécution du paquet npm local.

Résultat de référence : 7 fichiers de tests, 43 tests réussis, aucun échec.
Le smoke test produit une session complète de 98 événements, quatre exécutions
de campagne, une reprise sans appel et une analyse de notation simulée.

Audit des dépendances :

```bash
npm audit
```

Résultat de référence : aucune vulnérabilité connue signalée par npm.

## Ce qui n'a pas été validé automatiquement

- Aucun appel facturable n'a été envoyé sans clés fournies par l'utilisateur.
- Les adaptateurs réels sont validés contre les types et SDK officiels, puis par
  des tests contractuels injectés ; un smoke test BYOK reste nécessaire pour
  chaque identifiant de modèle choisi.
- La qualité supérieure du débat doit encore être mesurée avec les livrables
  aveugles et la rubrique d'évaluation.
- La composante interactive contrôlée par l'utilisateur exige ensuite une étude
  utilisateur croisée.

## Risques résiduels acceptés pour 0.1

- `node:sqlite` est encore signalé comme expérimental par Node 24.
- Une annulation côté client peut ne pas arrêter le calcul chez le fournisseur ;
  le prototype comptabilise alors le plafond réservé comme coût incertain.
- Après un arrêt brutal au milieu d'une exécution expérimentale, la reprise au
  niveau du rapport évite de refaire les exécutions terminées, mais pas les
  appels partiels du rapport inachevé. `--retry-failed` avertit explicitement de
  ce risque.
- Les tarifs sont fournis par l'utilisateur et peuvent être inexacts.
- L'égalisation des tokens de sortie n'égalise ni les tokens d'entrée ni le
  calcul interne entre modèles.
- Le prototype limite volontairement la session à un cycle et trois rôles.

## Condition de passage à 0.2

Ne pas ajouter terminal, édition autonome, Git ou worktrees avant :

1. un smoke test BYOK réussi pour les trois fournisseurs choisis ;
2. un petit pilote aveugle conforme à
   [`rubric-v1.md`](../evaluation/rubric-v1.md) ;
3. une décision humaine documentée de poursuivre, pivoter ou arrêter.
